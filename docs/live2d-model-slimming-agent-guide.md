# Live2D 模型入站瘦身指南（Agent 操作规约）

版本：1.0  
适用范围：将新 Live2D 模型接入本网站前的人工审计、可选派生优化与复检。  
依据：仓库根目录 `10.29.txt`；实际实现需在每次任务重新核实。

## 1. 目标与硬边界

模型瘦身是网站展示目标下的人工资源审计与可回滚派生处理，不是压缩率竞赛。优先保留模型显示、Idle/动作、表情、LookAt、LipSync（若模型支持）、Physics、拖拽和缩放所需能力；只有证据证明是网站不需要的服装/道具切换能力且无有效引用时，才可提出剔除候选。

- 原始模型不可变：不得原位覆盖、删除、重命名或重写原始文件。
- 网站素材目录默认禁止 Agent 写入；本项目 `AGENTS.md` 明确禁止复制、上传、删除或重建 `public/` 中的 Live2D 素材。未另行取得符合项目规则的明确授权前，只审计和出报告，不生成或放置派生模型。
- 禁止新增仓库脚本、CLI、Adapter、自动映射/索引/manifest/哈希缓存系统。允许一次性只读检查，不保存自动化工具。
- 不读写 `.env*`、密钥、密码、私钥或真实联系方式；不执行 Git、部署或预览，除非任务另有明确要求。
- 不编造参数 ID、配置字段、模型能力或运行时行为。证据不足就标记“需人工确认”或 `NOT_MEASURED`。
- 性能运行时工作先于素材变更。不要以删除素材来绕开 Runtime 问题。

## 2. 先核实当前网站需求

任务开始先阅读仓库 `AGENTS.md`、本指南、`package.json`、锁文件、模型注册/角色/行为配置，以及实际 Live2D Canvas、Runtime、加载器和清理逻辑。不要把旧路径或历史盘点当成事实，也不要读取 `.env*`。

追踪并记录实际链路：

1. 网站入口到 Live2D Canvas、Runtime、PIXI Application 的所有权。
2. 唯一帧更新路径（PIXI ticker、`autoUpdate`、任何 RAF/`model.update`）。不得新增第二条更新循环。
3. 模型 URL 与注册表、角色引用、mapping、有效 behavior profile 的优先级。
4. model3 JSON `FileReferences` 到 MOC、纹理、motions、expressions、physics、pose、user data 等实际文件的完整引用链。
5. Runtime 实际调用的 LookAt、LipSync、表情和动作；模型缺少某能力应优雅跳过。
6. 模型切换与销毁路径，以及交互/resize/visibility 监听清理行为。

本网站 Live2D 的有效保留能力以当前 Runtime 和有效配置为准。至少检查：正常模型展示与透明/裁切表现；已配置表情和动作；模型确有对应参数时的 LookAt 与 LipSync；已引用 Physics/Pose/UserData；拖拽、缩放、触控；角色切换后清理与再次加载。不要因某个资源不在显眼界面就判定无用。

## 3. Gate A：只读资产盘点

目标模型不明确时先询问；不要默认处理全部模型。针对每个目标模型记录 ID、model3 JSON 路径、注册状态、mapping/profile 来源和当前素材根。逐项解析真实 `FileReferences`，依引用图而非目录猜测。

记录以下可复核事实：

- MOC 文件字节数；每张被引用纹理的路径、格式、真实宽高、文件字节数。
- 纹理张数、最大单图面积、总像素面积，以及 `width × height × 4` 的解码内存粗略估算。它不等于实际 GPU 峰值。
- motion/expression 的模型引用、mapping 条目和有效 profile/Runtime 选择之间的对应关系。
- 参数组和真实参数 ID；无法从清单/模型数据确认时写“未核实”，不可推造。
- Physics、Pose、UserData、DisplayInfo 及其他 JSON 引用目标是否存在。
- 目录中未被直接引用的文件和全项目搜索结果。孤立文件不等于垃圾，外部/厂商依赖不明时保留待确认。
- 登记路径与磁盘路径不一致、未登记模型、断链、大小写/Unicode/空格风险。

只读盘点可用一次性命令或图片元数据查看；不得保存扫描脚本。基线和无法测量项必须如实标记 `NOT_MEASURED`。

## 4. Gate B：唯一判定表 K-01 至 K-10

判定项只使用以下表格，不要在报告其他部分另造第二份删除/保留名单：

| ID | 判定对象 | 规则 |
|---|---|---|
| K-01 | model3、MOC、被引用纹理及 FileReferences 资源 | 保留；依赖链完整前不得删。 |
| K-02 | 有效 behavior profile、角色解析或 Runtime 实际选择的 motion/expression | 保留；核实配置覆盖优先级后判断。 |
| K-03 | 展示与交互所需参数及已映射 LookAt/LipSync 参数 | 保留真实存在并实际需要的能力；不得虚构 ID。 |
| K-04 | 展示、裁切、交互或 Runtime 需要的 Physics/Pose/UserData/显示信息 | 保留；用途不明时待确认。 |
| K-05 | 已证明仅用于网站不需要的服装/道具切换，且无代码、配置、mapping 或展示依赖的项目 | 仅为剔除候选；须列出搜索范围和证据，获授权后在合规的隔离工作副本处理。 |
| K-06 | 没有发现直接引用的孤立文件 | 需人工确认；不能按“未引用”自动删除。 |
| K-07 | 用途不明、隐藏部件可能性、冲突或证据不足项 | 需人工确认；默认保留。 |
| K-08 | 纹理尺寸/数量可能高于目标设备或展示需求 | 优化候选而非功能性删除；测量像素成本、显示尺寸和设备目标后评估。 |
| K-09 | 未登记模型或注册路径不一致 | 需人工确认；不得自动登记/删除。 |
| K-10 | 已登记但文件或引用缺失 | 需人工确认；报告断链和影响，不猜替代项。 |

每个判定必须附模型 ID、结论、方法、文件/JSON 路径、引用搜索范围、证据和下一步。不能仅凭文件名、大小、4096/8192 后缀或压缩率作删除结论。

## 5. 纹理派生优化原则（仅在授权与项目规则都允许时）

优先验证纹理是否存在对目标显示无贡献的空白/边缘，以及实际画布显示大小、设备 DPR 和纹理采样需求。先在独立且可恢复的工作副本评估候选，不接触原件或 `public/`。

- 不盲目统一缩小全部贴图；禁止放大源图。
- 4096/8192 是复核信号，不是自动删除或降采样门槛。手机候选 2048、桌面候选 4096 只是初始评估值，不是质量保证。
- 保留透明通道、颜色/Alpha 质量与纹理图集 UV 布局。Live2D 贴图常包含透明区域与紧密 atlas；裁边、改图集尺寸、重排、重新压缩均可能破坏 UV 或透明边缘。
- 派生前记录源文件与目标文件映射、目标分辨率/格式、处理理由及可恢复备份位置。输出必须与原件隔离；若不能建立合规的工作副本或备份，停止修改。
- 先验证派生候选在模型 JSON 原引用结构下可加载，再按目标设备和典型场景对比边缘、细节、透明晕边、遮罩、表情/动作；回归失败则放弃该候选。
- 不编辑 MOC 二进制或重导模型结构，除非任务单独授权且具备官方兼容工具、原工程和明确回滚验证计划。

## 6. Gate C：写入授权与恢复条件

实际素材变更必须同时满足：用户明确指定要改哪些模型/内容；Gate A/B 完成并通过证据评审；项目资产规则允许写目标目录；有独立工作副本、清晰备份/恢复路径及报告位置。任一条件不满足，停在只读盘点和建议阶段。

变更前列出目标文件、派生文件、可能的引用改动、备份位置和复原步骤。报告放在独立目录而非模型目录。未经明确授权不得改网站 Runtime 来掩盖模型问题。

## 7. Phase 2：最小化人工变更

只处理已授权的 K-05 项目或明确批准的 K-08 派生优化。逐项执行并记录：原始路径、派生路径、依据、操作、备份/恢复方式和模型引用是否改变。保留待确认内容。若发现新依赖、配置冲突、无法安全回退、画面/功能不可验证或需要模型专用 Runtime 分支，立即停止并提交问题。

## 8. Phase 3：同范围复检

按原 Gate A 盘点范围重新检查，并完成适用的 C 清单。至少核对：

- C-01 登记/角色/真实素材 URL 一致性。
- C-02 model3 `FileReferences` 每条引用存在且路径大小写精确。
- C-03 纹理尺寸、字节数、总像素面积和解码估算前后对比。
- C-04 纹理引用集合与目录差集；孤立项单独报告。
- C-05/C-06 表情与动作对 mapping、有效 profile、Runtime 选择的可追溯关系。
- C-07 参数/LookAt/LipSync 真实能力与缺失时的优雅跳过行为。
- C-08 Physics/Pose/UserData 等引用与展示依赖。
- C-09 mapping schema 和配置覆盖优先级。
- C-10 文件名、相对路径、大小写、空格和 Unicode 一致性。
- C-11 服装/道具候选的归类和完整引用搜索证据。
- C-12 原始素材未变、备份可读、派生路径分离。
- C-13 报告不在模型目录且无临时脚本混入。
- C-14 保留能力的实际回归；未测试标 `NOT_MEASURED`。
- C-15 对批准剔除项复用相同搜索范围，无残留引用/断链；待确认项仍保留。
- C-16 若涉及 Runtime，确认单一帧更新路径、通用加载和清理完整。

复检不得降低标准或把待确认写成通过。发现断链/回归时，停止交付该候选，按授权范围恢复备份或请求决策。

## 9. 推荐报告格式

1. 目标、模型范围、日期和授权状态。
2. 当前项目事实：素材根、入口/Runtime/ticker、配置来源及有效优先级。
3. 逐模型盘点：资源、引用链、纹理测量、能力与路径问题。
4. K-01 至 K-10 判定（唯一判定表来源）；逐项附证据或 `NOT_MEASURED`。
5. C-01 至 C-16 适用检查结果、方法和证据；不适用说明原因。
6. 变更与备份：没有修改就明确写“无”；原件是否保持不变。
7. 复检结果、回归场景、命令摘要和退出码。
8. 未测指标、待用户确认、风险与下一步。

不得把 build 通过描述成模型性能提升，也不得编造压缩率、FPS、加载时间或内存收益。性能指标未实测就标 `NOT_MEASURED`。
